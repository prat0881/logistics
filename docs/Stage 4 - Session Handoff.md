**SB2b endpoints SB3 consumes** (all `Executive+`, authenticated, under `/api/queries/:id`; shared types in `@svyft/shared`):
- `GET legs/:legId/eligible-ffs?broaden=bool` → `FreightForwarder[]` (ACTIVE, filtered by leg country/mode/DG; `broaden=true` drops country/mode but keeps the DG guard).
- `PUT legs/:legId/ff-selection` body `{ ffIds: string[] }` → `{ selected: string[] }` (reconciles `SELECT` quotes; ignores frozen `RFQ_SENT+` FFs; validates ids are ACTIVE → 400).
- `POST legs/:legId/distribute` body `{ submissionDeadline?: ISO, confirm?: boolean }` → `DistributeResult`.
- `POST distribute-all` body `{ submissionDeadline?, confirm? }` → `DistributeResult` (with `skipped: [{legId, reason}]`, reasons `nothing-selected`/`already-distributed`/gate-code).
- `DistributeResult = { rfqs: DistributeRfqEntry[], distributedLegIds: string[], skipped: {legId,reason}[] }`; `DistributeRfqEntry = { freightForwarderId, rfqId, rfqNumber, minted, accessToken?, legIds }`.

**⚠ SB3 gotchas (from the 2b build):**
- **Query rollup is a least-advanced-leg gate:** the query shows **"RFQ Sent"** only when **every** leg is ≥ `RFQ_SENT`. A partially-distributed query stays at its lower rollup. Render per-leg status; don't infer the query is fully sent from one leg.
- **Dup-guard:** `POST distribute` returns **409** when the leg's selected FFs are already sent (nothing fresh). Surface a **"confirm re-distribute"** prompt → resend with `confirm: true` (returns `skipped: [{reason:"already-distributed"}]` in SB2b; true re-send is SB6).
- **Validation:** **400** with `{ message, codes: [F1_INCOMPLETE_LEG | F4_LEG_NOT_READY | F5_DG_FF_CANNOT_HANDLE] }` on a gate failure → show inline on the leg panel.
- **Distribute All** returns `skipped` entries per leg — render which legs were skipped and why.
- The **raw `accessToken`** is returned once (on mint) in `DistributeRfqEntry.accessToken`; live FF emails are **SB5**, so the UI may optionally show/copy the portal link but nothing is sent yet.
- **RBAC:** every distribution action is **Executive+** (no role gating beyond auth) — the UI need not hide it from any signed-in role.

## Conventions & key learnings (Stage-4-specific — CRITICAL, reuse every sub-build)
- **Workflow:** `superpowers:writing-plans` (explore first) → `superpowers:subagent-driven-development` (fresh implementer per task, TDD RED→GREEN + per-task spec+quality review, **opus** whole-branch review) → PR. **New git worktree per sub-build off `main`.** Ledger `.superpowers/sdd/progress.md` is **gitignored scratch** (fresh each sub-build) — this handoff + the plan docs are the durable record. Models: **sonnet** implementers + task reviewers; **opus** final review + design-heavy tasks; **haiku** for pure-transcription tasks + small reviews.
- **⚠ FRESH-WORKTREE SETUP** (a new worktree off `main` has none of this): `pnpm install`; **copy `apps/api/.env` from the main checkout** (gitignored → provides `DATABASE_URL`); `pnpm exec prisma generate`; **`pnpm --filter @svyft/shared build`** (web/api resolve the BUILT `@svyft/shared`; a stale/absent `dist` fails web with *"Failed to resolve entry for @svyft/shared"*). Verify baseline: shared + web + api tests **+ `pnpm run lint`** green before starting.
- **⚠⚠ E2E TEARDOWN (the "11-hour hang" lesson):** ANY e2e that boots the full `AppModule` **MUST** `await moduleRef.close()` (or `app.close()`) in `afterAll` — otherwise the `@nestjs/schedule` cron's open `setInterval` keeps the process alive and **jest hangs indefinitely after the tests pass** (there is NO `forceExit` in `jest-e2e.json` — by decision; follow the `vessels.e2e-spec.ts` convention). Also make every e2e **self-contained**: create + delete its own `query`/`leg`/`FreightForwarder` fixtures (never `findFirst` ambient rows — that hard-fails on a clean CI DB).
- **⚠ LINT is part of verification** — CI's `build-test` runs `pnpm run lint`. Run `pnpm run lint` before every commit and the PR. Watch `@typescript-eslint/no-unused-vars`: no destructure-to-omit (`const { x, ...rest }`) — use `{ ...obj, x: undefined }`. (A missed lint red'd PR #24 once.)
- **⚠ DB SAFETY:** local Postgres on **`:5433`** (Docker/colima — may need `colima start` + `docker compose up -d`). Migrations are **additive** via `prisma migrate dev`. **If Prisma ever proposes a RESET/DROP, STOP** — it's a shared dev DB.
- **Extending the Extensibility Core (how 2a did it — reuse):** add leg forward edges via `StatusRegistry.contribute("leg", [...])` in a module's `onModuleInit` — **never edit a Stage-3 status file**; register a new machine via `StatusRegistry.register`. The **only** sanctioned Stage-3 edit is adding an entity branch to `DispatchingStateStore` (for a column-owned status). All status changes go through `StatusService.fire`. The **query rollup comes free** (the existing projector already maps leg RFQ_SENT/…/FULLY_QUOTED → query RFQ_SENT/Quoted).
- **Soft→hard FK (pattern, done in SB2b):** SB2a referenced the FF by a plain `freightForwarderId` (no relation); **SB2b promoted it to a hard FK** (`onDelete: Restrict` + `@@index`) and fixed SB2a's arbitrary-UUID fixtures to real FF rows. When a later sub-build hardens a soft ref, fix any fixtures passing arbitrary UUIDs in the same task or the FK breaks them.
- **CI must be green** (`build-test` = lint + typecheck + tests + build) before merge. Watch the CI run after pushing a PR (`gh pr checks <n> --watch`); do not assume green (PR #24 caught a lint miss).
- **Inherit the Stage-3 conventions** (`Stage 3 - Session Handoff.md` → "Conventions & key learnings"): shared-enum pattern (`const` obj + union + `Object.values as [X,...X[]]`, pinned by a `toEqual` test — never a TS `enum`); `PrismaExceptionFilter` (**P2003 NOT mapped** → guard FKs in services); `cookie-parser` **default** import in e2e; soft user refs (`actorId` etc. = plain uuid, no relation); web `fetchJson`/`postJson` + TanStack Query re-GET for derived fields; RHF + `zodResolver`.
- **RBAC (Stage-4 convention, settled in SB2b):** query/leg/RFQ **workflow** write endpoints are **Executive+** — authenticated only, **no `@Roles`** (matches the `LegsController` convention + Functional Spec §5.2). Only **master-data** writes (FreightForwarder/Client/Vessel) gate to `@Roles(Role.ADMINISTRATOR, Role.MANAGER)`. *(The earlier handoff note "distribution writes = Admin/Manager" was wrong — corrected.)*

## Known issues / carried notes (Stage 4)
- ✅ *(resolved in SB2b)* SB2a arbitrary-UUID fixtures → real FF rows; `@@index([freightForwarderId])` added; hard FF FK (`onDelete: Restrict`) landed.
- **⚠ RFQ access-token unrecoverable if the post-distribute fire loop dies** (SB2b opus review) — the raw token is returned once (never stored), only its sha256 hash persists, and `@@unique([queryId, freightForwarderId])` makes a retry take the amend branch (no token) → that RFQ's FF portal link can never be built. **Add a token re-issue path BEFORE SB5 composes links.** *(A background task was spun off for this.)*
- **⚠ Prod migrate pre-flight** — the `add_ff_hard_fk` FK validates existing rows, so `prisma migrate deploy` **aborts** if prod holds an `Rfq`/`Quote` with an unknown `freightForwarderId`. Verified clean on the **dev** DB only — run the orphan `SELECT` against prod before the next deploy (risk low: those tables are SB2a-new + no distribution has run in prod).
- **RfqSequence orphan rows** — `RfqSequence.queryId` has no FK to `Query`, so deleting a query leaves an orphan row (harmless — keyed by a dead uuid, never collides; proper fix = a schema FK cascade, an SB2a-model change).
- **CORRECTION — Prisma DOES support array filters:** the earlier claim "Prisma has NO `hasSome`/`has` on scalar/enum arrays" is **false** (verified in the generated client). SB2b filters eligibility in TS (correct + tested); a DB-side `where` (`availableCountries: { hasEvery }`, `modes: { has }`) would be strictly better for a future refactor.
- **`Quote.rfqId onDelete: Cascade`** (vs SetNull) — kept Cascade (a distributed quote belongs to its RFQ; SB6's change-order marks quotes **invalid**, not deleted).
- **"No Response" query status** + **Expired** handling → SB5 (scheduler/expiry).
- **Live email** (currently compose-&-log) + **TLS/domain** for the FF portal → before real external FFs (SB5 + a go-live gate).
