## Conventions & key learnings (Stage-4-specific — CRITICAL, reuse every sub-build)

- **Workflow:** `superpowers:writing-plans` (explore first) → `superpowers:subagent-driven-development` (fresh implementer per task, TDD RED→GREEN + per-task spec+quality review, **opus** whole-branch review) → PR. **New git worktree per sub-build off `main`.** Ledger `.superpowers/sdd/progress.md` is **gitignored scratch** (fresh each sub-build) — this handoff + the plan docs are the durable record. Models: **sonnet** implementers + task reviewers; **opus** final review + design-heavy tasks; **haiku** for pure-transcription tasks + small reviews.
- **⚠ FRESH-WORKTREE SETUP** (a new worktree off `main` has none of this): `pnpm install`; **copy `apps/api/.env` from the main checkout** (gitignored → provides `DATABASE_URL`); `pnpm exec prisma generate`; **`pnpm --filter @svyft/shared build`** (web/api resolve the BUILT `@svyft/shared`; a stale/absent `dist` fails web with _"Failed to resolve entry for @svyft/shared"_). Verify baseline: shared + web + api tests **+ `pnpm run lint`** green before starting.
- **⚠⚠ E2E TEARDOWN (the "11-hour hang" lesson):** ANY e2e that boots the full `AppModule` **MUST** `await moduleRef.close()` (or `app.close()`) in `afterAll` — otherwise the `@nestjs/schedule` cron's open `setInterval` keeps the process alive and **jest hangs indefinitely after the tests pass** (there is NO `forceExit` in `jest-e2e.json` — by decision; follow the `vessels.e2e-spec.ts` convention). Also make every e2e **self-contained**: create + delete its own `query`/`leg`/`FreightForwarder` fixtures (never `findFirst` ambient rows — that hard-fails on a clean CI DB).
- **⚠ LINT is part of verification** — CI's `build-test` runs `pnpm run lint`. Run `pnpm run lint` before every commit and the PR. Watch `@typescript-eslint/no-unused-vars`: no destructure-to-omit (`const { x, ...rest }`) — use `{ ...obj, x: undefined }`. (A missed lint red'd PR #24 once.)
- **⚠ DB SAFETY:** local Postgres on **`:5433`** (Docker/colima — may need `colima start` + `docker compose up -d`). Migrations are **additive** via `prisma migrate dev`. **If Prisma ever proposes a RESET/DROP, STOP** — it's a shared dev DB.
- **Extending the Extensibility Core (how 2a did it — reuse):** add leg forward edges via `StatusRegistry.contribute("leg", [...])` in a module's `onModuleInit` — **never edit a Stage-3 status file**; register a new machine via `StatusRegistry.register`. The **only** sanctioned Stage-3 edit is adding an entity branch to `DispatchingStateStore` (for a column-owned status). All status changes go through `StatusService.fire`. The **query rollup comes free** (the existing projector already maps leg RFQ_SENT/…/FULLY_QUOTED → query RFQ_SENT/Quoted).
- **Soft→hard FK (pattern, done in SB2b):** SB2a referenced the FF by a plain `freightForwarderId` (no relation); **SB2b promoted it to a hard FK** (`onDelete: Restrict` + `@@index`) and fixed SB2a's arbitrary-UUID fixtures to real FF rows. When a later sub-build hardens a soft ref, fix any fixtures passing arbitrary UUIDs in the same task or the FK breaks them.
- **CI must be green** (`build-test` = lint + typecheck + tests + build) before merge. Watch the CI run after pushing a PR (`gh pr checks <n> --watch`); do not assume green (PR #24 caught a lint miss).
- **⚠ SDD-execution gotchas (learned in SB4b — reuse):** (a) a worktree nested under the main checkout → `pnpm` MUST run `-C <worktree>` (or foreground-from-worktree); a **background** bash task does NOT inherit the EnterWorktree cwd — it silently installs/builds in the PARENT main checkout. (b) the api has **NO unit-test runner** — `pnpm --filter @svyft/api test` runs only `test/*.e2e-spec.ts`; put a guard/unit test there as `*.e2e-spec.ts` (a pure unit test in the e2e dir, no AppModule boot, runs fine). (c) CI runs `migrate deploy` only (**no seed**) → any e2e needing reference data (`FreightDensityFactor`, etc.) MUST call `seedReferenceData(prisma)` in `beforeAll` (mirrors `queries.e2e-spec.ts`). (d) **fix-subagent verifies MUST include `lint`**, not just tests (a `no-explicit-any` slipped through once). (e) a **haiku** subagent may confabulate its cwd/git state — never approve a destructive git op (`reset --hard`) from a confused subagent; verify + fix directly.
- **Inherit the Stage-3 conventions** (`Stage 3 - Session Handoff.md` → "Conventions & key learnings"): shared-enum pattern (`const` obj + union + `Object.values as [X,...X[]]`, pinned by a `toEqual` test — never a TS `enum`); `PrismaExceptionFilter` (**P2003 NOT mapped** → guard FKs in services); `cookie-parser` **default** import in e2e; soft user refs (`actorId` etc. = plain uuid, no relation); web `fetchJson`/`postJson` + TanStack Query re-GET for derived fields; RHF + `zodResolver`.
