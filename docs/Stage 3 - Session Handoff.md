## Conventions & key learnings (reuse in Plan 5)
- **Flow:** brainstorm → write plan (`superpowers:writing-plans`) → subagent-driven execution (`superpowers:subagent-driven-development` — fresh implementer per task, TDD, per-task spec+quality review, **opus** whole-branch review at the end) → finish via PR. New branch per plan (`feat/plan-N-<name>` off `main`); plan doc + implementation ship as one PR. Ledger: `.superpowers/sdd/progress.md` (gitignored — start fresh each plan). Models: **sonnet** implementers + task reviewers; **opus** final review.
- **Extensibility Core golden rules (enforced by real code — now proven on Query/Cargo):** never hand-write a status — go through `StatusService.fire` (owned) or `QueryStatusProjector.recompute` (derived/projected); never raw-write a user-editable field — route it through `ChangeMediator.apply(req, uow)` (declare its impact class; representative field for a multi-field patch = `ImpactRegistry.highestImpactField`). Type each impact map `Record<keyof …Input, ImpactClass>` for **compile-time completeness**.
- **Postgres generated column in Prisma** (Plan 4's `volumeCbm`): model it as `@default(dbgenerated("<exact db pull expression>"))` (the canonical introspected form) **and** hand-edit the generated migration's `DEFAULT (...)` line to `GENERATED ALWAYS AS (...) STORED`. Verify **`prisma migrate diff … --script` prints an empty migration** (zero drift). It's optional-in-create + Postgres rejects direct writes.
- **Soft user refs:** `assignedUserId`/`FileAsset.uploadedById` are plain nullable `@db.Uuid` with **no relation** (like `StatusTransition.actorId`) — decoupled + test-friendly. Because they land in `@db.Uuid` columns, **e2e tests must use a UUID jwt `sub`** (a synthetic `u-EXECUTIVE` sub would P2023).
- **Validation:** bind Zod at **param level** — `@Body(new ZodValidationPipe(schema))`, never method-level `@UsePipes`. Prisma errors → the global `PrismaExceptionFilter`; **P2003 (FK) is NOT mapped** → verify referenced ids in the service and throw `BadRequestException`.
- **Env timing:** read env at DI/call time (`LocalDiskStorage` reads `UPLOADS_DIR` inside its method), not a top-level const.
- **Shared enums:** `const` object + `(typeof X)[keyof typeof X]` union + companion `Object.values(...) as [X, ...X[]]` array pinned by a `toEqual` test, values matching the Prisma enum exactly. Never a TS `enum`.
- **exceljs typing:** `writeBuffer()`'s return clashes with Node's `Buffer` (its `.d.ts` shadows `Buffer`) → use `Buffer.from(await wb.xlsx.writeBuffer())`, **not** `as Buffer`.
- **CI gotcha:** CI runs a **fresh migrated-but-UNSEEDED** Postgres. Every test MUST be **seed-independent + self-cleaning** (upsert its own `QuerySequence`/`ChecklistDefinition` via `seedReferenceData`, create its own users/clients, delete by a unique prefix). **Verify against `prisma migrate reset --schema … --force --skip-seed` + `pnpm run ci` before pushing**, then `gh run watch`.
- **Ops lesson (prod seed incident, PR #10):** the deploy pins `IMAGE=<sha>` only for its shell, so a **manual `docker compose run --rm api …` falls back to the compose default `:latest`** — which was a **stale locally-cached image** (deploys only `pull` `:<sha>`). Use **`docker compose exec api …`** for one-off prod tasks (runs *inside the current container*), and note the deploy now `docker tag`s `:latest` to the deployed image. **Probe live routes by their real path** (`GET /queries` is 404 by design — the list is Plan 6; probe `POST /queries` → 401).

**Plan 4 tech-debt (deferred deliberately — schedule)**
- **Atomic `rowIndex` hardening:** cargo `create` reads `MAX(rowIndex)+1` under READ COMMITTED (no unique/lock) → concurrent same-query POSTs can duplicate an ordinal. **Deferred per spec §8.5** (last-write-wins); mitigated with deterministic read order `[rowIndex, createdAt, id]`. Harden with `@@unique([queryId, rowIndex])`+retry or a per-query counter when concurrency matters.
- **MSDS `FileAsset` outside the mediator tx:** `attachMsds` writes the disk file + `FileAsset` row before the mediated `msdsFileId` link — an orphan on post-store failure (low-prob). Move the row into the mediator tx (disk stays outside).
- **Impact-class re-validation before Stage 4:** re-check the `RfqDefining`/`Corrective` classifications in `query.impact.ts`/`cargo.impact.ts` against §11.1 before the change-order fork activates (Stage 4).

**Extensibility deferred (Stage 4+)**
- **ChangeOrder cascade + durable change-log:** `ChangeOrderStrategy` throws (unreachable); `ChangeLog` is a no-op sink. Go live with downstream work (RFQ/quotes). The `reopen` edge is built.
- **`fire` concurrency:** reads-then-appends under READ COMMITTED, no row lock (last-write-wins, §8.5). Pair a row lock / serializable+retry with the Stage-4 cascade that reads prior state from the log.

**Security / ops**

- **Container hardening:** non-root `USER` in `apps/api/Dockerfile`; DB-resilient health (`$connect` non-fatal; `/api/health/db` as readiness).
- **Multi-tenant:** global uniques (`Client.companyName`, `Vessel.imoNumber`, `ChecklistDefinition.itemKey`, `Query.queryCode`, `FreightDensityFactor.mode`) become composite `(tenantId, …)` when tenancy activates.
