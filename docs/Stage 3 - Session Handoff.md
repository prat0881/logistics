## Conventions & key learnings (reuse in Plan 6+)
- **Flow:** brainstorm → write plan (`superpowers:writing-plans`) → subagent-driven execution (`superpowers:subagent-driven-development` — fresh implementer per task, TDD, per-task spec+quality review, **opus** whole-branch review at the end) → finish via PR → **verify in prod**. New branch per plan (`feat/plan-N-<name>` off `main`); plan doc + implementation ship as one PR. Ledger: `.superpowers/sdd/progress.md` (gitignored — start fresh each plan). Models: **sonnet** implementers + task reviewers; **opus** final review. **Plan 5 proof:** 10 tasks, every task review clean; the reviews caught a real RFQ_READY recompute race (fixed with `await emitAsync`) and a Create-Query idempotency 500 (fixed to fire only DRAFT legs) that green tests alone missed.
- **Extensibility Core golden rules (enforced by real code — proven across Query/Cargo/Point/Leg):** never hand-write a status — go through `StatusService.fire` (owned) or `QueryStatusProjector.recompute` (derived/projected); never raw-write a user-editable field — route it through `ChangeMediator.apply(req, uow)` (declare its impact class; representative field for a multi-field patch = `ImpactRegistry.highestImpactField`). Type each impact map `Record<keyof …Input | "@create" | "@delete", ImpactClass>` for **compile-time completeness**.
- **Owned status columns** (Plan 5's `Leg.status`): the column is authoritative and written **in the same tx as the `StatusTransition` log** via the key-aware `DispatchingStateStore` (`entity === "leg"` → column; else → log). Firing an owned status against a synthetic id now needs a **real row** (a non-uuid id → P2023 on the column read; a missing row → P2025 on the write) — tests create real `Query`+`Leg` fixtures.
- **Postgres generated column in Prisma** (Plan 4's `volumeCbm`): `@default(dbgenerated("<exact db pull expr>"))` + hand-edit the migration's `DEFAULT (...)` to `GENERATED ALWAYS AS (...) STORED`; verify `prisma migrate diff … --script` prints an empty migration. (Plan 5 added no generated columns — leg roll-ups are derived-on-read.)
- **Derived-on-read** (Plan 5): `Query.freightMode`/origin/destination + per-leg roll-ups are computed in a `shapeQuery` mapper over a `Prisma.validator`/`QueryGetPayload`-typed row (never stored, zero drift). The isomorphic `validateRoute` is the single source of truth for the §10 catalogue — the Plan-6 browser runs it too.
- **Soft user refs:** `assignedUserId`/`FileAsset.uploadedById`/`StatusTransition.actorId` are plain nullable `@db.Uuid`, no relation. e2e tests must use a **UUID jwt `sub`**.
- **Validation:** bind Zod at **param level** — `@Body(new ZodValidationPipe(schema))`. Prisma errors → the global `PrismaExceptionFilter`; **P2003 (FK) is NOT mapped** → verify referenced ids in the service (points/legs pre-check `originPointId`/`destinationPointId`/`assignedCargoIds` belong to the query) and throw `BadRequestException`.
- **Env timing:** read env at DI/call time, not a top-level const.
- **Shared enums:** `const` object + `(typeof X)[keyof typeof X]` union + companion `Object.values(...) as [X, ...X[]]` array pinned by a `toEqual` test, values matching the Prisma enum exactly. Never a TS `enum`.
- **`cookie-parser` import:** e2e specs use the **default import** `import cookieParser from "cookie-parser"` (a namespace import throws under this repo's `esModuleInterop`).
- **CI gotcha:** CI runs a **fresh migrated-but-UNSEEDED** Postgres. Every test MUST be **seed-independent + self-cleaning** (own `seedReferenceData` + own clients/queries, delete by a unique prefix; a query delete cascades its points/legs/legCargo/cargo/checklist). **Verify against `prisma migrate reset --schema … --force --skip-seed` + `pnpm run ci` before pushing**, then `gh run watch`.
- **Ops lesson (PR #10):** use **`docker compose exec api …`** for one-off prod tasks (not `run`, which falls back to a stale `:latest`). **Probe live routes by their real path** — a Plan-5 route unauthenticated returns **401** (route exists + guard); a **404** means the old image is still live (`GET /queries` is 404 by design — the list is Plan 6).

**Plan 4 tech-debt (deferred deliberately — schedule)**
- **Atomic `rowIndex` hardening:** cargo `create` reads `MAX(rowIndex)+1` under READ COMMITTED (no unique/lock) → concurrent same-query POSTs can duplicate an ordinal. **Deferred per spec §8.5**; mitigated with deterministic read order. Harden with `@@unique([queryId, rowIndex])`+retry or a per-query counter when concurrency matters.
- **MSDS `FileAsset` outside the mediator tx:** `attachMsds` writes the disk file + `FileAsset` row before the mediated `msdsFileId` link — an orphan on post-store failure (low-prob). Move the row into the mediator tx.
- **Impact-class re-validation before Stage 4:** re-check the `RfqDefining`/`Corrective` classifications in `query.impact.ts`/`cargo.impact.ts`/`leg.impact.ts`/`point.impact.ts` against §11.1 before the change-order fork activates.

**Extensibility deferred (Stage 4+)**
- **ChangeOrder cascade + durable change-log:** `ChangeOrderStrategy` throws (unreachable — `ScopeResolver.downstreamWork ≡ false`); `ChangeLog` is a no-op sink. The `reopen` edge + the cargo→leg scope fan-out are built and waiting. `LegCargo.manifestSnapshot` + `Leg.totalChargeableWeight` stay null/reserved (the RFQ freeze + FF density are Stage 4).
- **`fire` concurrency:** reads-then-appends (+ now the column write) under READ COMMITTED, no row lock (last-write-wins, §8.5). Pair a row lock / serializable+retry with the Stage-4 cascade.

**Security / ops**
- **HTTPS + domain:** prod is HTTP-only on `:4096`, `COOKIE_SECURE=false`. When a domain lands → `docker-compose.caddy.yml`, set `SITE_ADDRESS`, flip `COOKIE_SECURE=true`.

- **Multi-tenant:** global uniques (`Client.companyName`, `Vessel.imoNumber`, `ChecklistDefinition.itemKey`, `Query.queryCode`, `FreightDensityFactor.mode`, `@@unique([queryId, legCode])`) become composite `(tenantId, …)` when tenancy activates.
